# Скрипт базовой настройки Linux-сервера - VPS Setup

Скрипт для комплексной первичной настройки и защиты VPS-сервера на базе Debian/Ubuntu.

## 📋 Описание

`setup.sh` — это bash-скрипт, который автоматизирует первичную настройку свежего VPS-сервера: обновляет систему, устанавливает базовые утилиты, настраивает Swap, выполняет hardening SSH, настраивает брандмауэр, защиту от перебора и автообновления.

## 🚀 Быстрый старт

### 🌟 Вариант 1: Скачивание и ручной запуск (рекомендуется)

####  Скачать скрипт
```bash
curl -fsSL -o setup.sh https://raw.githubusercontent.com/thealekseev/vps-setup/refs/heads/main/setup.sh
```
####  Сделать исполняемым
```bash
chmod +x setup.sh
```
####  Запустить
```bash
./setup.sh
```

### 🏎️ Вариант 2: Запуск одной командой

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/thealekseev/vps-setup/refs/heads/main/setup.sh)
```
### Проверка текущей конфигурации сервера
```bash
sudo ./setup.sh --check
```
#### Или короткий вариант:
```bash
sudo ./setup.sh -c
```


## ⚙️ Что делает скрипт (пошагово)

1. **Проверка среды**: Определяет ОС, проверяет права root и ждет освобождения блокировок пакетного менеджера.
2. **Обновление системы**: Выполняет `apt update` и `apt upgrade` с автоматическим принятием конфигов по умолчанию (`--force-confold`).
3. **Установка утилит**: Ставит базовый набор (`curl`, `htop`, `jq`, `git`) и инструменты безопасности (`ufw`, `fail2ban`, `auditd`, `rkhunter`).
4. **Настройка Swap**: Создает файл подкачки 2 ГБ, если он отсутствует, для стабильности работы.
5. **Синхронизация времени**: Устанавливает часовой пояс UTC и включает `chrony` или `systemd-timesyncd`.
  
### 🔒 SSH Hardening (Ключевой этап)

- Предлагает создать нового пользователя с правами sudo. Проверка на допустимые символы и защиту от зарезервированных имён.
- Проверяет наличие SSH-ключей. Если их нет, генерирует пару `ed25519` и безопасно сохраняет приватный ключ во временный файл.
- Опционально меняет стандартный порт 22 на случайный свободный порт (10000–60000).
- Применяет строгие настройки через `/etc/ssh/sshd_config.d/99-hardening.conf` (отключение паролей, root-логина, X11 и т.д.).

### 🛡️ Дополнительные меры защиты

- **Брандмауэр (UFW)**: Запрещает весь входящий трафик, разрешает исходящий. Открывает порты SSH (с лимитом подключений `limit`), HTTP (80) и HTTPS (443 TCP/UDP).
- **Защита от перебора (Fail2Ban)**: Настраивает бан IP-адресов на 1 час (с прогрессивным увеличением до 1 недели) после 3 неудачных попыток входа, используя UFW как механизм блокировки.
- **Твики ядра (Sysctl)**: Включает защиту от SYN-флуда, спуфинга, скрывает указатели ядра (`kptr_restrict`) и запрещает создание hardlink/symlinks для непривилегированных пользователей.
- **Автообновления**: Включает `unattended-upgrades` для автоматической установки патчей безопасности.

### ✅ Финализация

- ✅ **Обновляет сигнатуры `rkhunter`**
- ✅ **Подтверждение перезапуска:** Скрипт явно спрашивает, готовы ли вы к разрыву текущей SSH-сессии.
- ✅ **Безопасный перезапуск SSH:** Итоговая конфигурация и команда для подключения выводятся ДО перезапуска, чтобы вы не потеряли данные при разрыве сессии.
- ✅ **Выводит сводку с инструкциями**

## ⚠️ КРИТИЧЕСКИ ВАЖНЫЕ ПРЕДУПРЕЖДЕНИЯ

### 🛑 НЕ ЗАКРЫВАЙТЕ текущую SSH-сессию после завершения работы скрипта!

Сначала откройте **новое окно терминала** и проверьте возможность подключения с новыми параметрами (порт, пользователь, ключ). Если что-то пошло не так, у вас останется активная сессия для отката изменений.

### 🔑 Если скрипт генерировал SSH-ключи

Приватный ключ сохраняется в файл `/root/GENERATED_PRIVATE_KEY.txt` с правами `400` (только чтение для root). Скопируйте его содержимое на свой локальный компьютер и **немедленно удалите этот файл** с сервера после успешной проверки входа.

### 🆘 Если вы потеряли доступ

Используйте веб-консоль (VNC/KVM), предоставленную вашим хостинг-провайдером, для входа в систему и исправления конфигурации `/etc/ssh/sshd_config.d/99-hardening.conf`.

## 🧹 Действия после запуска

### 1. Проверьте вход (в новом окне терминала!)

```bash
ssh -p <новый_порт> <новый_пользователь>@<IP_сервера>
```

### 2. Удалите временный файл с приватным ключом (если он был создан)

```bash
rm -f /root/GENERATED_PRIVATE_KEY.txt
```

### 3. Проверьте статус защиты

```bash
sudo ufw status verbose
sudo systemctl status fail2ban
```

### 4. (Опционально) Настройте алиасы в вашем локальном `~/.ssh/config`

Для удобного подключения без постоянного указания порта и ключа:

```
Host myserver
    HostName <IP_сервера>
    User <новый_пользователь>
    Port <новый_порт>
    IdentityFile ~/.ssh/id_ed25519
```

## 🔄 Откат изменений (Troubleshooting)

Скрипт создает резервные копии критических файлов с суффиксом `.bak.initial`. Если что-то пошло не так (например, вы заблокировали себя), используйте VNC-консоль провайдера и выполните:

```bash
cp /etc/ssh/sshd_config.bak.initial /etc/ssh/sshd_config
cp /etc/ufw/user.rules.bak.initial /etc/ufw/user.rules
cp /etc/sysctl.conf.bak.initial /etc/sysctl.conf
systemctl restart ssh
ufw disable
```

## 📦 Требования

- **ОС:** Debian 11+ / Ubuntu 20.04+
- **Доступ:** root или пользователь с sudo-правами
- **Сеть:** активное интернет-соединение
- **Утилиты:** `curl` или `wget` для загрузки скрипта
